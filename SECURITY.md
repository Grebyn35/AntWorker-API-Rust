# Security

## Reporting a vulnerability

Report a vulnerability in private: on this repository's page on GitHub, under "Security", choose "Report a vulnerability". Open no public issue, discussion or pull request for it.

Say what the vulnerability lets someone do, the release or the commit that has it, and the steps that show it.

## What to expect

One person maintains this template, as time allows. A report is read and answered on a best-effort basis: no answer, and no fix, is promised within a set time.

A fix comes in a release, and `CHANGELOG.md` marks it as a security fix, so that a fork can port it. Only the newest release receives fixes.

## A product built on a fork

A fork replaces this file with its product's own policy: where its users report a vulnerability, and how soon the product answers a report, fixes a vulnerability, and updates a component that has one. The template sets none of those times for it.
